## Issues, ranked

### 1. [CRITICAL — client bug, Dev Note #4] The game hangs when a character dies

*"BIG BUG: Something breaks when a character dies, the lock-in is not possible and the timer bar goes
away, forcing game to go on forever."* Investigated. The **hot-seat** turn-boundary is robust
(`seatRoster()` filters `alive`; `beginTurn` resets; `openSeat` skips dead seats). The suspect is the
**networked** path: `playResolution` calls `beginTurn()` for *both* modes (`app.ts:1932`), and
`beginTurn → openSeat` (`app.ts:925-932`) has a branch — *"no living roster → `endTurn()`"* — that for
a networked client **auto-submits** (`net.submit([])`) the instant a resolution leaves this seat's
unit(s) **downed** (respawning). The client is then locked with no window it can act on, which reads as
"lock-in impossible, timer gone, forever." **Fix: backlog DEATH-HANG (client, CRITICAL)** —
**reproduce via the harness** (a networked match where a unit dies/downs), root-cause the turn-boundary,
and make a downed/empty-roster seat present a clean **waiting** state (timer from the server window,
lock-in available or an honest "your units are down" hold) instead of an auto-submit that looks frozen.
A regression must drive a death and assert the *next* turn is playable for **both** the downed seat and
its opponent, hot-seat **and** networked.

### 2. [MED — client, Dev Notes #2, #3] Damage previews still hide the centre bonus and self-damage

*#2: "Cinder's preview for damage on her auto attack should show the extra damage to the center
correctly … AUDIT ALL DAMAGE PREVIEWS." #3: previews should show 11-to-self / 22-to-enemies (Whirling
Cleave), 12-to-enemies / nothing-on-self (Shockwave), 19-to-self / 38-to-others (Seismic Rupture).*
AIM-PREVIEW-TRUE fixed the **shape**; the **numbers** are still off — the axis/inner sub-bands and,
newly, the **caster's own recoil damage** are not shown. **Fix: backlog PREVIEW-NUMBERS-AUDIT
(client)** — the damage tell equals the engine's resolution for **every** ability, at every previewed
tile, including: Cinder's inner (22 centre / 14 ring), Bastion's axis (+8 line), and — the new
dimension — the **caster's own tile** carrying its `selfDamagePct` recoil (11 whirl, 19 Seismic; none
for Shockwave). Property-style: preview number at tile == resolved number at tile, for the roster.

### 3. [LOW — data, Dev Note #3] Ravok's Whirling Cleave should cost him 11

`cleave` has no `selfDamagePct`, so CASTER-SAFE leaves Ravok at 0 self; the owner wants 11. **Fix:
backlog RAVOK-RECOIL (data)** — `selfDamagePct: 50` on Whirling Cleave (11 of 22); Shockwave stays 0
self / 12 enemies; Seismic Rupture already 19/38. Ruled in edge-cases (RAVOK-RECOIL).

### 4. [LOW — data, Dev Note #5] Kestrel's Slipstream should last 2 turns

`slipstream` is `[{haste, duration:1}, {energized, duration:1}]`; the owner wants **duration 2** for
both. **Fix: backlog KESTREL-SLIPSTREAM-2T (data)** — both riders `duration: 2`.

### 5. [LOW — client, Dev Note #1] Cinder's burn isn't a visible debuff

*"Cinder burn should be a debuff that players can see."* The DoT is a `damageOverTime` **status** on the
unit (with per-turn amount + source), but the client's status pips don't render it. **Fix: backlog
BURN-VISIBLE (client)** — the `damageOverTime` status shows as a debuff pip (a burn marker with its
remaining turns), like root/slow/reveal. Read the existing status; no engine change.

### 6. [LOW — client, Dev Note #6] Line-attack previews feel laggy

*"Vex's and other line attack previews seem to be a little laggy, can you make it more smooth?"* The
per-hover boundary re-derivation (AIM-PREVIEW-TRUE) for a long line may re-tessellate every mousemove.
**Fix: backlog LINE-PREVIEW-SMOOTH (client)** — throttle/memoise the hover re-derivation (the boundary
only changes when the quantized aim direction changes, not every pixel), so the line preview tracks
smoothly. Out of scope: changing the geometry.
