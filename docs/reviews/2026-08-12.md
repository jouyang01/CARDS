## Issues, ranked

### 1. [Medium — latent, blocks item 6] Attacking/taking damage must *clear* Stealth, not just be masked by Reveal
`packages/engine/src/vision.ts:227-233` (`isConcealedFrom`) checks `reveal` before
`stealth`, so an attacker who gains Reveal-for-one-turn *appears* to drop stealth — but
the Stealth status is still on the unit and re-hides it the moment Reveal expires. This
contradicts GAME_SPEC §6 ("Stealth … broken by attacking or taking damage"). The
current code is correct; the trap is for whoever implements item 6.
**Fix:** when statuses/abilities apply (item 6), remove the `stealth` status outright on
attack and on taking damage — do not lean on the Reveal it grants. Baked into item 6's
acceptance criteria below and ruled in `edge-cases.md`. (Builder already flagged this in
`DECISIONS.md` (7); this promotes it so it can't be lost.)

### 2. [Medium — blocks item 7] Dash semantics are undefined: walked `path` vs `teleport`, and trap-triggering
Data mixes two dash models under one umbrella:
- `data/characters/vex.json` `combat_roll`: `shape: "path"`, effect `teleport`,
  flavor "Quick roll up to 3 squares."
- `data/characters/wisp.json` `blink`: `shape: "square"`, effect `teleport`, "Ignores
  walls."
- `data/characters/wisp.json` `shadowstep_strike` (ult): `shape: "square"`, `teleport`
  + `damage`.

GAME_SPEC §2 and `edge-cases.md` say "Dashes trigger traps they cross" and
"damage-dealing dashes deal their damage in this phase" — but a `teleport` that skips to
a destination has no squares to "cross." Item 7's AC ("dash-into-trap") can't be
implemented without a rule for which dashes traverse squares. **Fix:** ruled below in
`edge-cases.md` as PROPOSED — `path` dashes walk square-by-square (blocked by
walls/units, trigger every trap entered, damage the first enemy in the path);
`square`/teleport dashes ignore intervening squares and walls and trigger only a trap on
the *destination*. See issue 4 for the `combat_roll` data mismatch this exposes.

### 3. [Low-Medium — preventive] CI determinism guard is narrower than golden rule #1
`.github/workflows/ci.yml` greps only `Math.random|Date.now|new Date(`. Golden rule #1
also forbids **float game math** and **unstable object-key iteration**, and other clock
sources (`performance.now`) slip through. The guard reads as "determinism is enforced"
when it enforces a third of it.
**Fix:** widen the grep to include `performance\.now` and a float-literal check scoped
to `packages/engine/src` (e.g. fail on `[0-9]\.[0-9]` outside comments), or add an
ESLint rule banning `for..in`/`Math.random`/floats in the engine package. Current code
passes either way — this is a ratchet, not a bug report.

### 4. [Low — Designer] `combat_roll` flavor and effect kind disagree
`data/characters/vex.json` `combat_roll` is a "roll" (implies traversing squares, per
its own description "Dodges Blast-phase attacks aimed at your old position") but carries
the `teleport` effect (implies skipping them). Once issue 2's ruling lands, either make
it `shape: "path"` with no `teleport` effect (a walked dash — its reposition *is* the
path, and it should trigger traps it rolls over) **or** keep `teleport` and accept it
ignores walls/traps like Blink. Designer to reconcile; do not leave both.

### 5. [Low — wiring note for item 9] Trap ability effects need place-vs-trigger routing
`data/characters/vex.json` `overwatch_trap` lists `[{trap, amount:20}, {reveal,
duration:2}]` flat. `TrapState.onTrigger` (`types.ts:145-152`) is where the Reveal
belongs — the implementer of item 9 must route non-`trap` effects into `onTrigger`
(applied to the victim on entry), not apply them at placement. Added to item 9's AC.

### 6. [Nit] Root `npm test` runs the engine workspace only
`package.json` `"test": "npm run test -w @cards/engine"`. CI calls this same script, so
if the client or server ever gains tests they will silently not run in CI. Fine today
(engine is the only tested package); switch to `--workspaces --if-present` when that
changes.
