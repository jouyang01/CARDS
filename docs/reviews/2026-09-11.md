## Issues, ranked

### 1. [MED — client, owner-directed] Manual move waypoints (Dev Note #1)

*"You should be able to manually set different waypoints to move your unit around an enemy, a trap,
or any obstacle … Hold down the Shift key while executing a movement command on each tile you want to
step on sequentially … Every time you click on a tile, your effective movement range should change
(decrease typically)."* **The engine already supports this** — `validateMovePath` walks an arbitrary
ordered step list (adjacency, MET1 cost, terrain, corner rule, budget) and `runMove` walks a given
`movePath` verbatim, no re-pathfinding. So the whole feature is client input. **Fix: backlog
WAYPOINTS (client)** — while Shift is held each click appends the clicked tile as the next step of
`draft.movePath` (refused/marked if it is not a legal step from the previous), and the remaining-move
readout decrements by that step's cost (1 ortho / 2 diagonal); releasing Shift keeps today's
direct-line auto-route. Submits as an ordinary `movePath`. Ruled in edge-cases (WAYPOINTS). Must
still honour MOVE-FOG (a fogged enemy is not an obstacle at plan time).

### 2. [MED — server/client] The lobby's start trigger and the leftover route (OQ #2, #4, #10)

With picking in the protocol, a 4-player 2v2 **fills before anyone picks**, so the full-room
auto-start fires over the empty lobby. The Builder shipped a narrow interim guard (hold while a pick
is outstanding); it does not help a room that has not started picking. **Ruled: LOBBY-START** — a
room with a lobby starts on the **start button** (`RoomHub.start()`, gated on `lobbyReady`), not on
being full; **retire the full-room auto-start together with the lobby screen** (same slice, so a
networked match always has a reachable start), and **delete `POST /rooms/:code/start` in that same
slice.** Folded into M3-LOBBY-UI. Until then the interim guard stays.

### 3. [LOW — server] A zero-character seat in 1v1 (OQ #6)

`deriveSeats` can hand a second player on a one-character team an empty list (`?? []`) — a pick
screen that asks for nothing, reachable only in 1v1. **Ruled: SEAT-ZERO** — refuse the join that
would create a zero-character seat (at most one player per character on a team); spectators stay a
post-v1 option. **Backlog SEAT-ZERO-GUARD** (server, small, low), beside the started-room refusal.

### 4. [INFO — no code] The chase admissibility gate is intentional (OQ #1)

`walkChase` follows by sightline at any range; `planUnit` still admits a chase only within range or
to a last-known square. **Ratified as-is** — you may *order* a chase only on a target you can see
(range+LoS) or remember; the loop widening was deliberate and the gate mirrors client targeting (you
cannot click a fogged enemy). Widening the gate would be dead code without a broader vision change.
No fix; recorded so it does not get "fixed" into a leak.
