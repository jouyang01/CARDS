## Dev Notes routed

### 1. [CRITICAL — client/server, Dev Note #1] The death hang, explained — and DEATH-HANG-2 may not cover it

*"Explanation of the Death Hang: Ravok died to a Lumen attack. Timer Vanished. The 'winning' team's lock in
froze."* This is the evidence I asked for last session, and it points at a **different path than
DEATH-HANG-2 fixed.** DEATH-HANG-2 handles a turn **nobody** can take (a double KO leaving both teams down,
tie held). The owner describes a **single** kill — Lumen kills Ravok — with the **winning, fully-alive**
team's lock-in freezing. A single kill in sudden death makes the killer's team *lead*, which by the
SUDDEN-DEATH ruling **ends the match** — and DEATH-HANG-2 explicitly does nothing once
`state.status !== 'active'` (`hub.ts:650`). The server *does* clear the timer when the match finishes
(`hub.ts:513`), which is exactly *"Timer Vanished"* — so the most likely remaining defect is the **winning
client not transitioning to the victory screen** when a sudden-death kill both ends the match **and** downs
a seat on the same turn, leaving it frozen on a board with no timer and a dead Lock In. **Fix: backlog
DEATH-HANG-3 (CRITICAL, reproduction-first)** — build the owner's exact scenario over NET-E2E (sudden
death, one team lands a **match-ending** kill on the other), assert the **winning** client reaches the
end/victory screen cleanly (no frozen lock-in, no orphaned window). If the shipped code already handles it,
the test locks it; if not, fix the transition. **Do not assume DEATH-HANG-2 covers this — it is a different
turn state.**

### 2. [MED — client, Dev Note #2] You can't see an ally's movement

*"We need to be able to see ally's movement commands as well to know where they're moving."* TEAMMATE-PLAN-
VISIBLE draws a teammate's move route (`theirs.movePath`, `app.ts:1481`) — **but only for a relayed plan**:
the guard at `app.ts:1478` (`if (relayed === undefined) continue`) skips the route for a **locally-locked**
teammate, so in hot-seat a locked character's move is invisible (only its ability preview shows). And a
**chasing** teammate shows nothing, because a chase has no plan-time route. **Fix: backlog
TEAMMATE-MOVE-VISIBLE (client)** — draw a locked teammate's move route for **both** local and relayed
plans, and show a **chase indicator** (a link to the chased enemy) when the teammate's order is a chase.
Drive it through the real wiring for both hot-seat and networked. (Builder OQ #3 — the relayed route is the
router's path, not the teammate's clicked corners — folds in here: acceptable, watch it, don't chase pixel
parity.)
