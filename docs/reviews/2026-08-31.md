## Issues, ranked — all in the pending spec, not in shipped code

### 1. [HIGH — would have reversed shipped behaviour and broken a test] CAMO-REVEAL narrowed the existing reveal

The 2026-08-30 Spec Note told the Builder to *"gate the penalty on being concealed at the moment of
acting … so acting in the **open** does not arm a future reveal"*, and listed *"a unit acting in the
open gains no reveal"* as a required test. That narrows the **existing, shipped, unconditional**
reveal-on-dealing-damage (`resolve.ts:912` dash, `:1106` blast). It is wrong twice:

- **It breaks a shipped test.** `packages/engine/test/attribution.test.ts:178` drives a plain
  unconcealed unit at `(0,4)` on an open map, has it attack, and asserts it gains `reveal`.
- **The stated justification is false.** The note called the open-field reveal *"a no-op anyway"*.
  It is not: `reveal` lasts `REVEAL_ON_ATTACK_TURNS = 2` (`constants.ts:26`) and beats brush
  (`vision.ts:231`). Removing it lets a unit shoot from open ground on one turn and disappear into
  brush the next with no penalty — which is the mechanic's entire purpose.

The owner's rule *adds* camouflage triggers (catalyst, taking damage); it never asks for the
existing one to be removed. **Fix applied:** the item is now explicitly **additive** — dealing
damage reveals you concealed or not, unchanged; the three new triggers are concealed-gated. The
open-field case is now a required *regression guard* instead of a required behaviour change.

### 2. [HIGH — unbuildable as written] STEALTH-DURATION named an ability that does not exist

The AC, the Spec Note, the 2026-08-30 review and the edge-cases ruling all said `veil_and_decoy`.
The roster id is **`veil_decoy`** (`data/characters/wisp.json`); grepping the repo for
`veil_and_decoy` returns documentation only. **Fix applied** in both the backlog and the ruling.

Two related things the Builder needed and did not have:

- **The `decoy` effect's `duration` is dead data.** `spawnDecoy` (`resolve.ts:713`) computes
  `expiresOnTurn = castTurn + 1` from the turn counter and never reads the effect's `duration`. The
  backlog's "the decoy value is unchanged" was right but unexplained, which invites a well-meaning
  "align it to 2" that changes nothing. Now stated, and flagged as a validation gap — `VALIDATE-KEYS`
  rejects *unknown* keys, not known-but-ignored ones.
- **The AC named an e2e that does not exist.** It claimed *"the STEALTH-CONFIRM e2e now passes … the
  stealthed Wisp is absent from the enemy seat"*. `render.spec.ts:530` never reaches an enemy seat
  and never asserts stealth — it drives the cast from Wisp's own seat and checks the purple decoy
  and a log line. **Fix applied:** the AC now asks for the enemy-seat assertion at unit level, where
  the Builder already put it, and explicitly says not to add the e2e.

### 3. [MED — a plumbing change for nothing] CAMO-REVEAL pointed at a `Vision` the resolver has not got

The Spec Note said to check `brushPatchAt(...)` from `vision.ts`, adding *"thread it in or pass a
`brushPatchAt` closure"*. But **`resolve.ts` never builds a `Vision`** — no `buildVision`, no
`Vision` import anywhere in the file. Following that note means threading a new object through
`runPrep` / `runDash` / `runBlast` / `fireCatalyst` to answer a question the resolver can already
answer: it holds `board` in all four, and `terrainAt(board, p)` returns `'brush'` directly
(`board.ts:150`, brush indexed at `:133`). **Fix applied.**

### 4. [MED — genuine spec gap the Builder would have hit mid-implementation] "Concealed" was undefined

`isConcealedFrom` (`vision.ts:230`) takes an `observerPos`, because the brush adjacency exception
makes concealment **per-observer**: a unit in brush is hidden from a distant enemy and visible to an
adjacent one. So "is this unit concealed?" has no observer-free answer, and a per-observer gate
would reveal a unit to some enemies and not others off one action — incoherent. The owner's wording
is *"while inside a camouflage zone"*, which is a tile. **Ruled** in edge-cases: the gate is
`terrainAt(board, unit.pos) === 'brush' || hasStatus(unit, 'stealth')`, independent of who is
looking.

### 5. [LOW — wrong pointer] DASH-OCCUPIED cited the wrong function

The prohibition claim cited `teleport()` at `resolve.ts:292`. Line 292 is `teleportDestination`, a
four-line helper that extracts a catalyst's aim. The real function is at **:963** with the occupancy
check at **:967**. `walkCharge` at `:933` was correct. **Fix applied** in both documents. Also
corrected: CAMO-REVEAL's reveal/`breakStealth` line numbers were a commit stale (912/1106, and
1079/495/873/333 for the new call sites).

### Also folded into the spec

- **Build order + shared surface** are now explicit at the top of the backlog: DASH-OCCUPIED parts
  (3) and (4) are the same `commitAim` commit; CAMO-REVEAL's red tile and LAST-KNOWN's ghosts should
  both reuse the TRAP-INDICATOR plate/overlay-band pattern rather than inventing a third render style.
- **LAST-KNOWN statefulness gotcha:** `fogView` is pure and memoised on `(state, team)`
  (`app.ts:196-202`), so it re-runs on any state change. Putting the last-seen memory inside it means
  every repaint overwrites the memory with the current frame. The map belongs in the app layer and
  should be passed *into* the view builder, keeping `fog.ts` a pure function of
  `(state, team, memory)`.
- **STEALTH-DURATION's test churn is now named precisely:** `stealth-confirm.test.ts`'s first
  `describe` is synthetic and survives; the second was written as a bug reproduction and must invert
  into the proof of the fix (`:138`'s `toBe(1)` → `2`; the `duration: 2` counterfactual at `:142`
  becomes redundant and should fold into the positive assertion).
- **DASH-OCCUPIED part (2) is explicitly deferrable** — no roster dash exercises the knockback
  exception — but the Builder must *state the choice in the commit message* rather than silently
  drop it.
