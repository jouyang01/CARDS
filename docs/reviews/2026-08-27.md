## Issues, ranked

No correctness defects (no code shipped). Three items to carry into the build:

### 1. [Medium — latent validation gap, fix in DASH-IMPACT] Unknown ability fields pass silently
The three `impact` blocks were added to `data/` and the suite stayed green — which means
`validateAbility` **ignores unknown fields** rather than rejecting them. That is why the inert
data is safe today, but it also means a **typo'd field (`impcat`, `destinaton`) would be
silently dropped** with no error. **Fix:** DASH-IMPACT's validation must be *additive new
coverage* (validate `impact`'s shape/phase/radii), and the Builder should consider a stricter
"reject unknown keys" pass on `AbilityDef` so future data typos fail loudly. Noted in the
DASH-IMPACT Spec Notes.

### 2. [Low — live balance change ahead of its engine, tracked] Ravok's knockback is nerfed now, impact is inert
Bullrush is `knockback 2→1` **live** while its `impact:{destination:2}` is **inert** until
DASH-IMPACT ships — so right now Bullrush is a single-target 14 + knockback-1 charge, strictly
weaker than before. This is the Designer's intended "weaker than designed, never stronger"
interim (the `chargeHits`/`free` convention), but it means **Ravok is temporarily undertuned in
any playtest between now and DASH-IMPACT.** Acceptable; flagged so a "Ravok feels weak" playtest
note isn't mistaken for a real balance problem. Prioritizing DASH-IMPACT closes the gap.

### 3. [Low — resolved, was a live conflict] MET1 vs HITBOX1 disagreed on the circle metric
The Designer surfaced that MET1 ruled `circle`/`square` **Manhattan** while HITBOX1's circular
hitbox made circles **Euclidean discs** — both RULED, in quiet conflict. **Resolved to Euclidean**
via AIM-METRIC (owner-approved: "aiming is measured in distance"); MET1's circle/square clause is
marked superseded in edge-cases. This was the one item the Designer flagged as "needs an owner
call" — the same-day owner directive resolved it, so it is closed, not open.
