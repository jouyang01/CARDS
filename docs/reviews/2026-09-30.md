## Dev Notes routed

### 1. Aegis's Intercept change → backlog INTERCEPT-GUARD (engine + data + client)

*"Make sure you see Aegis' intercept change and spec it for the builder."* The Designer's redesign is
complete and RULED (owner directive): `docs/design/intercept-guard.md` + the edge-cases entry + the
2026-08-17 DECISIONS note. It rebuilds Intercept from a teleport-plus-self-shield into the Bodyguard's
thesis — teleport adjacent to an **ally** within 5; for the rest of the turn, **damage that ally would
take is dealt to Aegis instead**; Aegis alone gains an **18** shield. It is a **new mechanic** (a `guard`
EFFECT_KIND, the first since DOT-HOT) and ships as **one engine+data+client commit**. **Specced in full as
backlog INTERCEPT-GUARD**, carrying the design doc's numbers, the seven `guard` rulings, the targeting
model, and the eight required tests verbatim — see BACKLOG. This is the next session's main work.

### 2. Sudden death → ruled SUDDEN-DEATH (edge-cases) + backlog SUDDEN-DEATH-TEST

*"Rule on sudden death: The rule is that in Sudden Death, the next kill wins."* **Ruled in edge-cases
(SUDDEN-DEATH), and it closes Builder session-12 OQ #1.** The good news for the Builder: this is **already
how the engine behaves** — tied at the turn limit sets `suddenDeath` and continues, and because the win
check re-runs the `turn >= turnLimit` comparison every subsequent turn, the first kill differential wins
(`resolveOutcome`, `resolve.ts:2925`). So the ruling formalises shipped behaviour rather than commissioning
a mechanic. It is **unbounded — no artificial cap, no alternate tiebreak** (the owner's rule is that a
*kill* decides it). The one draw that survives is a simultaneous Double-KO that carries both teams to the
kill target at once, consistent with the existing Mutual-damage ruling. **Spec: backlog SUDDEN-DEATH-TEST**
(test-only) to lock "the next kill wins" against regression — the current `formats.test.ts` proves sudden
death is *entered* but never that a kill *ends* it.
