## Issues, ranked

### 1. [MED — client, Dev Note #1] The board is too small; the HUD wants a re-layout

*"The main game screen is too small in comparison to the buttons."* The owner supplied a screenshot
with a full target arrangement. **Fix: backlog HUD-LAYOUT (client)** — reflow the in-match HUD per the
five directives (verbatim in the item): catalysts to the **bottom-left** beside the character portrait;
Move/Sprint/Chase/Clear to the **bottom-right**; the **Lock In bar + timer** into where the catalysts
were (centre, above the ability row); **score + teams** to the **top** of the window; and the **board
expands** to fill the space the timer/lock-in bar vacated (as large as fits). Layout/CSS + the HUD
component tree; no engine, no protocol. The existing timer-bar, score, catalyst and movement components
move rather than change behaviour.

### 2. [MED — server bug, OQ #2] A room that survives a DO restart becomes unjoinable

`durable-object.ts` mints socket ids from a **module-level counter** (`seat-${nextSocketId++}`) that
**resets to 0 when the DO is evicted**. A room restored from storage still holds `seat-0`, `seat-1`;
the next socket to connect is *also* minted `seat-0`, so its ordinary join is refused as
`duplicateSeat` and closed — the room looks unjoinable, identical to the bug just fixed. **Fix: backlog
SOCKET-ID-STABLE (server)** — socket/seat ids must not collide across a DO restart: derive the next id
from the **persisted** seat set (max existing + 1), or use a non-resetting id source. This is a real
production bug (eviction happens), not just a test artifact — worth doing before the next playtest.

### 3. [LOW — client, OQ #4] The rest of the native `title` tooltips still lag

CATALYST-TIP-FAST converted the lobby's catalyst buttons; `hud.ts:410` (status chips), `hud.ts:346`
(Time Bank button), `app.ts:1255–1268` (topbar portraits) and `inspect-panel.ts:90` (inspect-panel
catalyst chips) still use native `title` with the same reveal delay. **Fix: backlog TOOLTIP-SWEEP
(client)** — convert them to the instant `tooltip.ts` (now that it exists). Closes the tooltip family
the Dev Note opened.

### 4. [LOW — client, OQ #3] `?chars=` should error on a bad id, not fall back

DEV-CHARSELECT falls back on an unknown character id; its neighbour toggles **error** (DECISIONS
2026-09-18: *"mistyping the map you wanted to test is the one behaviour a dev toggle must not have"*).
**Ruling: a dev toggle must fail loudly, not silently seat the wrong roster** — **backlog
DEV-CHARSELECT-ERROR** (tiny): an unknown `?chars=` id shows a visible error and does not boot a
fallback roster. Consistency with MAPTOGGLE.

### 5. [TRIVIAL — OQ #5, #6] Two cheap cleanups

- **OQ #5:** the Skip-during-playback control shares the `hud-lock` class with Lock In; a rename to
  `hud-skip` makes the DOM say what it means. Fold into HUD-LAYOUT (it touches the HUD anyway).
- **OQ #6:** `app-harness.ts` drives only a networked seat; the hot-seat pass-the-device handover is
