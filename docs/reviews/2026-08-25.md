## Issues, ranked

### 1. [Medium — process/release fragility] RENDER-VERIFY gates the Pages deploy
Because `deploy-pages.yml` fires on a *successful* CI run and RENDER-VERIFY is in CI, a red (or
flaky) render job now **blocks all publishing** — and that job depends on a ~280 MB CDN browser
download + a headless GPU stack. An infra hiccup there would block shipping an urgent engine or
docs fix. **Ruling: decouple** — the Pages deploy should gate on the **core CI** (engine tests,
typecheck, client build), not on the render smoke test. Keep RENDER-VERIFY running on PRs as a
pre-merge signal (a red check is the guardrail); just don't let it hold the release hostage.
**Fix: backlog CI-decouple.**

### 2. [Medium — playtest blocker] `iron-basin` (4v4) is validated but unreachable
`main.ts` hard-codes `duel-arena`, so the 4v4 map can't be played or playtested. **Fix: backlog
MAPTOGGLE** — a dev-only map/format selector (full lobby is M3). Without it, 4v4 has zero real
exercise before M3.

### 3. [Low — Designer note] Turn-1 spawn safety has one tile of margin
Separation 13 vs worst-case threat 12 (`move 4 + MAX_ABILITY_RANGE 8`) on both maps — passes,
but any inward spawn nudge or a raised `MAX_ABILITY_RANGE` trips it. Not a defect; the Designer
should hold `MAX_ABILITY_RANGE = 8` and the spawn columns where they are.

No correctness defects in the shipped batch.
