## Done well (one line)

INTERCEPT-GUARD wrote its exclusions as *absences from a chokepoint* rather than negated conditions inside
it — so the next damage source that forgets about the guard lands where it was aimed instead of silently
redirecting something the ruling excludes. That is the difference between a rule and a rule that stays true.

## Dev Notes from the playtest — routed, ranked by severity

### 1. [CRITICAL — client/server, Dev Note #5] The death → can't-lock-in freeze is back, in sudden death

*"The Death bug and then not being able to lock-in and breaking the game is still happening, playtest made
it happen during sudden death."* DEATH-HANG (PR #94) made a downed networked seat *hold* instead of
auto-submitting, and it works for the case it was tested on — but **no automated test covers a death in
sudden death**, and the Builder's own session-13 OQ #5 lists exactly the untested networked scenarios. I
traced it: a networked client has one seat with possibly several units (`app.ts:435`), `seatRoster()`
filters to living units, the hold fires only when *all* are down (`app.ts:1096`), and `holdDownedSeat()`
starts **no timer** — it relies on the server's DOWN-SEAT-SKIP (`#canAct`, `hub.ts:595`) resolving the turn
once the *living* seats submit. That chain is sound in normal play; the freeze is in some interaction I
cannot reproduce from the code alone, and past the turn limit (sudden death) is where it surfaced. **Fix:
backlog DEATH-HANG-2 (CRITICAL) — reproduction FIRST**, through the NET-E2E harness: a death that downs a
seat *during sudden death* (turn past `turnLimit`, kills tied), asserting the surviving side can lock in and
the turn resolves. The prior fix shipped without this coverage; this one does not.

### 2. [HIGH — client (+maybe engine), Dev Note #1] Intercept should let the player pick the landing square

*"When Aegis uses intercept, the player should be able to only choose a square that is adjacent to an ally.
Right now you can only choose the ally square and can't choose which adjacent square to go to."* My
INTERCEPT-GUARD spec deliberately auto-landed (nearest-open, no choice UI); the owner wants the choice,
because which side of the ally Aegis stands on decides which lane he blocks and whether he ends in cover.
**Ruled INTERCEPT-LANDING-CHOICE (edge-cases); backlog same.** Aim becomes "an empty square orthogonally
adjacent to an ally within 5"; the guard binds that ally; Aegis lands where chosen. Fizzle (blocked at
resolution) ruled the **whole ability**, cooldown spent (closes OQ #1).

### 3. [MED — engine, Dev Note #3] Chase runs to the stale tile — audit it

*"Chase needs to follow better, sometimes the character chases directly to the tile the last character was
on even if we know where the chase target went. Audit Chasing."* I confirmed the **team-vision** half is
right — `teamHasSightline` checks *every* team unit, not just the chaser (`vision.ts`), so a teammate's
sight does count. The remaining suspects, both real: (a) the chase **snapshot** is the post-*normal*-move
board (`resolve.ts:2404`), so a target that is **itself chasing/dashing** is pursued to its pre-chase tile;
(b) the fog fallback reads `lastKnown`, which is only written at **end of turn** (`resolve.ts:3059`) — so
when the team loses sight at end of Move, the chaser walks to the target's **previous-turn** square, not
where it was seen going this turn. **Fix: backlog CHASE-AUDIT (engine) — reproduction-first**, since the
owner asked for an audit: build the "target moved, we saw it, chaser went to the old tile" case and fix
whichever of (a)/(b) it exercises. Do not "improve" chase pathing generally — reproduce the reported miss.

### 4. [MED — client, Dev Note #4] You can't see a teammate's locked-in plan

*"You need to see your teammates actions when they lock in."* Golden rule #5: teammates see each other's
plans, and the server **does relay a team's submissions** to teammates (`hub.ts:474`). So the gap is the
**client not rendering** a relayed teammate order (their committed ability area, move path, guard link) on
your board. **Fix: backlog TEAMMATE-PLAN-VISIBLE (client) — drive it through the real wiring**: two seats
on one team, one locks in, assert the other's board shows the committed plan (the hot-seat path already
draws a locked character's plan — extend it to a networked teammate).

### 5. [LOW — data, Dev Note #2] Warding Wall should Slow, not Weaken

*"AEgis Warding wall should do slow instead of weaken."* One field. **Fix: backlog WALL-SLOW (data)** —
`warding_wall`'s second effect `weaken` → `slow` (same `duration: 2`). Note: the description and any
"Weakened next turn" wording move to "Slowed"; TTK-INVARIANT is unaffected (trap, not a measured skill).

### 6. [LOW — client render, Dev Note #6] The nameplate hides behind Aegis's model

*"Nameplate still is hidden by Aegis' character model."* `nameplates.ts` is the *model* (what a plate
says); the occlusion is a **render-depth** problem — the floating plate now sits behind a tall rigged mesh
that the box never was. **Fix: backlog NAMEPLATE-DEPTH (client render)** — the nameplate draws **on top**
of the character (depth-test off / high render order / overlay pass), for models and boxes alike.
