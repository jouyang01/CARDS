- **AOE-LoS matches the #179 spec, and the one judgment call inside it is the right one.** The centre-LoS
  shelter went into **`circleSquares`** (`shapes.ts`), not `runBlast` — so "a disc reaches what its centre
  can reach" is one rule in the one function that builds a disc, and the Blast hit-set, the falloff ring, a
  dash `impact`, a `perTile` trap, the `abilityFired` footprint and the client's own `circleSquares` call in
  `targeting.ts` all inherit it and cannot disagree. That is golden rule #2 done correctly and it is why
  preview parity is not a second implementation. Verified against the spec, point by point:
  - **Shelter:** `circleSquares` ends with `if (!hasLineOfSight(board, center, p)) continue;` — walls-only,
    integer-exact, deterministic, from `vision.ts`. Behind a wall → 0, open → full.
  - **Cover from the centre:** the circle path calls `isBehindCover` with the aimed **centre** as
    `attackerPos` (`coverOrigin(def, casterPos, aim)` → `coverFrom: blastOrigin`); COVER-EDGE 50% applies
    iff the centre→unit line crosses the faced edge. `stamped` was added beside `fixedDamage` so a delayed
    blast still owes cover while RECOIL still skips it — the two are correctly kept distinct.
  - **Aiming:** a new `teamCanSeeSquare` (deliberately **not** `teamCanSee`, which asks the *unit* question —
    a lobbed grenade must be aimable at the exact tile a hidden enemy stands on) gates aim over the turn's
    **opening** team vision; `lobbed` picks arc-over-walls vs `hasLineOfSight(caster, centre)`. A test pins
    `teamCanSeeSquare` against `visibleSquaresForTeam` over a whole board so the aim gate and the fog cannot
    drift.
  - **Delayed detonation:** `PendingDelayedAbility` now carries `damage` (scaled by `outgoingDamagePct` at
    cast) and `centre`, both optional so an older serialized state still detonates; LoS + cover resolve at
    detonation-time positions.
  - **Phase order and dash immunity are untouched** — the diff to `resolve.ts` is comments, the
    `coverOrigin`/`board` threading, and the delayed-blast stamp; Prep→Dash→Blast→Move and dash immunity are
    not in the change.
- **Tests ship with the behavior (golden rule #3), and were mutation-checked.** `aoe-los.test.ts` is new
  (+482 lines); four existing fixtures were re-specced *because the new rule genuinely changes the answer*
  (`basic-inner` aimed from out-of-vision so every cast was silently refused; `caster-safe`'s RECOIL case

## Done well (one line)

Putting the shelter in `circleSquares` instead of `runBlast` is the invariant-by-design move: preview
parity, dash impacts, trap carpets and the falloff ring all inherit one integer-exact LoS rule and *cannot*
drift from it — the same class of fix as COVER-EDGE's "cannot shoot across ⇒ cannot walk across."

## Issue #1 — CRITICAL: Wisp is invisible because her idle clip flings the mesh off the board (Dev Note 1)

**Root-caused from the shipped `wisp.glb`, not guessed.** Wisp loads as a model (she has a `wisp_idle`
clip, so she is not the box fallback), and `modelBounds` measures her **correctly** — geometry Y-extent
**1.897** (~1.9 tiles), feet at `minY ≈ 0` — so she is neither mis-scaled nor sunk through the floor, and
her material is clean (doubleSided, textured, no alpha). She is **animated away**:

- She is the **first model built via the Rodin import path** (`rodin_bake_lowpoly.py`), and **every one of
  her ten clips carries a large `Hips` translation** baked in a space unrelated to the bind skeleton. The
  bind `Hips` sits at `Z ≈ −1.09`; the `wisp_idle` track sits at **`Z ≈ +22`** (first key `[−0.40, 2.13,
  22.52]`), and other clips range to `Z ≈ +101` (knocked_down), `+31` (veil, also `Y ≈ −16`), `+33`
  (flurry).
- `instance()` (`character-model.ts:410`) plays `idle` **immediately on load**. The mixer overwrites the
  Hips translation with the ~22-unit track value, and through the `Armature` +90° X convention that
  displaces the whole skinned mesh ~22 units off the board — off-screen. Hence invisible, not a box.
- **`build_glb.py --in-place` does not save it.** It *pins horizontal drift to frame 0* (`strip_root_motion`,
  `build_glb.py:79`) — but frame 0 is itself 22 units off, so pinning the drift leaves the baseline; and its
  "local Y is world-up after `automatic_bone_orientation`" assumption is wrong for these clips (veil `Y ≈
  −16`, bola `Y ≈ −8` carry huge Y offsets too). The shipped idle `Z` still **varies** 9.9→23.3, so the
  strip did not even take on that axis. The build session's "horizontal → 0.0u" verification measured
  per-clip *drift*, not the absolute offset from bind — a true statement about the wrong quantity.

**Fix (spec'd as WISP-INVISIBLE-FIX, CRITICAL, first).** The engine owns unit position and the renderer
places/lerps the unit **group** on its tile, so a clip must supply in-place motion only. The systemic fix is
a **client-side root lock** (ruled **MODEL-ROOT-LOCK**): after `mixer.update`, neutralise the root bone's
**horizontal** translation to its bind value each frame, keeping vertical (death fall / crouch), measured in
world space so it is robust to any authoring axis. This is in the Builder's lane, is Vitest-testable without
a browser, fixes Wisp, and makes **every future imported model immune** — the whole roster is coming down
this same path. The asset/pipeline correction (rebuild `wisp.glb`; make `--in-place` re-base to bind, not
pin to frame-0; drop the local-Y-is-up assumption) is the paired **ART** item **WISP-GLB-REBAKE**, so the
`.glb` stops carrying a 20-unit lie — but it is the second line of defence, not the guarantee.

## Issue #2 — Dev Note 3 (Ravok Shockwave LoS) is already satisfied by AOE-LoS

Shockwave is `shape: circle, range: 0, radius: 2`, centred on Ravok's own square. Under AOE-LoS its hit-set
is `hasLineOfSight(Ravok, unitTile)`, so a unit behind a wall from Ravok already takes 0 — that **is**
"requires line of sight," from the burst's centre. **No new work**: the moment AOE-LoS ships (it has),
Shockwave stops splashing through walls. Ruled **AOE-LoS-SELF-BURST** (Shockwave/Cleave/Seismic
Rupture/Warding Halo are `range:0` self-circles and need no `lobbed`). Nothing to schedule.
