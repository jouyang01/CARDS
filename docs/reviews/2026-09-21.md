## Issues, ranked

### 1. [HIGH — client, Dev Notes #1, #2, #3] The aim preview draws a shape the engine doesn't resolve

*#1: "Bastion's Crushing Slam Center hit does not account for preview correctly." #2: "Aegis Shield
Bash still shows a cone preview, it should be the 3 tile wide rectangle." #3: "View the PR #90 Designer
and ensure it makes it into the next builder spec."* All three are one fix. The Designer's
**AIM-PREVIEW-TRUE** (owner-flagged VERY IMPORTANT, `docs/design/aim-preview-true.md`) diagnoses it:
the client draws two objects that cannot agree — the smooth AIM2 *input region* and the `expandShape`
*answer* — which under HITBOX1 disagree by up to half a tile at every edge and rotation. **Fix: backlog
AIM-PREVIEW-TRUE (client, HIGH)** — the continuous graphic becomes the **analytic boundary of the
engine's own tile-centre predicate** (region ⊕ disc(½)), so a tile lights **iff its centre is inside
the drawn shape**, exactly, for every shape. Aegis's `beamWidth` cone then draws as the **inflated lane
(a rounded rectangle), not a wedge** (#2 fixed); the cone congruence fixes Bastion's footprint (#1).
**Spec Note I add for #1:** the axis/inner **sub-band** tells (Bastion's +8 centre line via
`axisSquares`, Cinder's core via `innerSquares`) must draw **congruently from the same engine
predicate**, not only the outer boundary — "Center hit does not account for preview correctly" is about
which tiles show the centre bonus, so the band, like the boundary, must be the engine's answer.
