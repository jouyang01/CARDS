## Dev Note — "how close are we to a multiplayer room lobby?" (Dev Note #1)

**Close. The core loop is built and works end-to-end today, locally / same-network.** You can now:
create a room (M3-ROOM-CREATE — a form that mints a code and follows it), share the `?room=CODE` link,
have both sides pick characters + catalysts on the blind-across-teams pick screen (M3-LOBBY-UI), press
start once everyone's picks add up (LOBBY-START, `lobbyReady`-gated), and **play a networked match that
renders on the 3D board with correct per-seat fog** (M3-NET-BOARD). Turns submit over the socket and
resolve server-side. That is a working lobby.

**What stands between "works locally" and "a friend and I can play over the internet":**

1. **Waiting/locked UI (M3-WAIT-STATE, small).** After you submit, the board sits armed with no "turn
   locked / waiting for opponent" state (OQ #3). Ruled; specced.
2. **Disconnect/reconnect UX (M3-CONN-STATE small + M3-RECONNECT larger).** A dropped socket just
   freezes the board silently (OQ #4). The client-says-so is small; the rejoin-and-resync is bigger.
3. **A discoverable Create-room link (CREATE-LINK, tiny).** `?create` exists but nothing links to it —
   a host has to know to type it (OQ #5).
4. **A server turn timer (M3-TIMER).** Blocked on M3-WAIT-STATE (it renders onto that seam).
5. **Actually deploying it (M3-DEPLOY).** It runs on localhost today; reaching a friend over the
   internet needs `wrangler deploy` + Pages, which **needs your infra decisions** (Cloudflare account,
   wrangler config). This is the real-world gate, not an engine problem.

**Estimate:** ~1 Builder session lands the polish (wait-state, disconnect banner, create link); M3-TIMER
is ~1 more; then **M3-DEPLOY is the step that needs you** (a Cloudflare account + a go-ahead) before it
is internet-playable. Functionally the lobby is essentially done; what remains is turn-loop polish and
deployment.
