## Issues, ranked

No correctness or determinism defects. The items below are the M3 security interim and OQ-driven
scope calls — nothing to fix in shipped code.

### 1. [MED — security, and the next priority] The networked build broadcasts full state (Builder OQ #5)
`turnResolved` sends full state to every seat — the M3-HIDDEN interim, exactly as specced. But it
means the **networked build currently leaks strictly more than the hot-seat**: the event log carries
every enemy action, and the hot-seat at least fogs its render. This is the golden-rule-#5 boundary
and it is unbuilt. **Fix: M3-HIDDEN is the immediate next item** — confirmed, prioritised at the top
of the M3 roadmap. Do not deploy anything (M3-DEPLOY) before it.

### 2. [LOW — reachable bug, guardable now] A post-start joiner gets a phantom seat (Builder OQ #4)
If a player leaves mid-match (freeing a seat) and a new socket joins it, that socket gets an **empty
control map** and still **counts toward the lock total**, so the turn can never complete. **Ruled:**
a started room **refuses fresh joins**; a freed seat is **reserved for its original occupant to
reclaim via M3-RECONNECT**; spectators are out of scope for v1. **Fix: backlog M3-JOIN-GUARD** — the
one-line refuse-join guard can land now (closes the bug); the reclaim path is M3-RECONNECT's. Ruled
in edge-cases.

### 3. [LOW — playtest reach] Networked matches are full-room-only until a start control exists (Builder OQ #3)
The auto-start trigger is a **full** room (correct — starting on "both teams present" seats later
joiners controlling nothing, decision 8), so a deliberately short 2-player 2v2 can't start over the
network without calling `RoomHub.start()`. **Fix: backlog M3-START** — a minimal "start now"
protocol message (RoomHub.start() is already public) so a short room is playable before M3-LOBBY,
which lets M3-HIDDEN be exercised on a 2-player room. Ruled in edge-cases.

### 4. [LOW — coverage gap] The camo red tile still has no composited test (Builder OQ #1)
CAMO-SEED's *hook* shipped (`?scenario=in-brush`), but the e2e was **cut rather than shipped as a
tautology**: `isCamoRed` cannot separate a lit thicket (~`158,45,37`) from a Lambert-shaded red unit
(~`179,78,70`) by pixel-counting — a no-thicket frame and a seeded frame both score 22. Good call not
to ship a test that passes for the wrong reason. **Fix: backlog CAMO-E2E-FINISH** — have the seed
**report the squares it placed** (echo into the setup title / a dev `window` global) so the e2e can
`pixelAt` the known camo square instead of counting the frame. Small; low priority (the *rule* is
unit-covered by `camo-reveal.test.ts`; only the *compositing* is unproven).
