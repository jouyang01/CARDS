## The Dev Question — the 404 is expected, and here is the real play URL

*"`https://cards-rooms.lockstepcards.workers.dev/` is showing 404 not found. How do I fix this?"*
**Nothing is broken.** That URL is the **backend server (the Worker)**, not the game. The Worker
answers exactly three routes (`worker.ts:4-6`) — `POST /rooms`, `GET /rooms/:code/ws` (the socket),
`GET /rooms/:code` — and returns 404 for everything else, including the root `/`. A 404 there is the
Worker **working**; a broken deploy would fail to resolve or 500. **The game you play is the client**,
served by GitHub Pages at **`https://jouyang01.github.io/CARDS/`** (base path = repo name).

**One owner step remains for multiplayer to connect (issue 1 below):** set the repo *variable*
`WORKER_ORIGIN` to `cards-rooms.lockstepcards.workers.dev`, then let the Pages build re-run. Until then
the deployed client is same-origin and the networked path reaches no server (Builder OQ #4).

## Issues, ranked

### 1. [MED — owner action, not a code bug] The client isn't pointed at the Worker yet (OQ #4)

The Pages build reads `VITE_WORKER_ORIGIN` from the repo variable `WORKER_ORIGIN`
(`deploy-pages.yml:54`), which is **empty until the owner sets it** — so the deployed client tries its
own origin (`github.io`) for the socket and multiplayer silently does nothing. **Fix (owner, one
setting):** GitHub repo → Settings → Secrets and variables → Actions → **Variables** tab → New
repository variable, name `WORKER_ORIGIN`, value `cards-rooms.lockstepcards.workers.dev`; then re-run
the Pages deploy (push any commit to `main`, or re-run the workflow). No code change. This is the last
wire between "deployed" and "playable over the internet."

### 2. [MED — server] Locked-in orders don't survive a DO eviction (OQ #2)

TIMER-PERSIST persisted the deadline and the charges; the **third** in-memory thing is this turn's
submissions (`hub.ts` `#submissions`). A DO evicted mid-turn resumes the right window but every seat
reads **unlocked** and must re-lock. Cheap to fix (a plain object on the record, same shape as `bank`).
**Fix: backlog SUBMISSIONS-PERSIST** — persist `#submissions`; it is the gap between "the clock
survives" and "the turn survives." Not urgent (eviction mid-turn is rare and it self-heals into a
re-lock), but it belongs on the list now the game is live.

### 3. [INFO — ruled/flagged] Three small ones (OQ #1, #5, #6)

- **OQ #1 (RECONNECT-DETACH):** ratified and folded into edge-cases (the restore-detaches-all rule).
- **OQ #5 (presence not in Playwright):** accepted coverage boundary — marked seats need two clients +
  a running Worker, a shape the hot-seat render suite lacks; it's unit/integration-covered (15 tests,
  incl. an end-to-end drop against a real hub). A two-client e2e harness is a possible future item
  (NET-E2E, low), not scheduled.
- **OQ #6 (enemy presence count):** ruled **allowed** — an enemy "1 of 2 present" count is coarse
  status like the lock-count, not a pick leak (BLIND-PICK is about picks/plans). Optional small
  addition to NET-PRESENCE-UI; enemy ids/picks stay hidden.
