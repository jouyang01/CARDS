## Issues, ranked

### 1. [Medium-low] Energized boosts the passive energy drip, contradicting the ruling
`combat.grantEnergy` scales every gain by Energized, and `resolve.endOfTurn`
(resolve.ts:680) routes the flat `+5` passive through it — so an Energized unit banks 7,
not 5. The edge-cases ruling ("Energized scales earned energy, not the passive drip";
GAME_SPEC §5 lists the passive as separate from "energy gained") says the passive is not
boosted. Code and ruling disagree. **Fix: backlog item E1** — add the passive without
Energized scaling; keep ability/on-hit energy scaled. Small, balance-affecting, ships with
a regression test.

### 2. [Low] Cover uses a corner-inclusive test; LoS is corner-exclusive
`combat.isBehindCover` (`segmentsIntersect`, endpoint touches count) grants cover on an
exact corner graze, while `vision.hasLineOfSight` lets a corner graze *see through*. Both
are internally consistent and the asymmetry favors the defender, but it breaks the "one
geometry, one corner convention" principle. Ruled acceptable for v1 (edge-cases); optional
unification is **backlog E2**. Impact is limited to exact-corner shots.

### 3. [Low — behavior confirmation] A Slow/Root landing in Blast bites the same turn's Move
Move budget is computed after Blast (resolve.ts:599), so a Blast-applied Slow truncates —
and Root cancels — that victim's Move the same turn, even though the path was validated at
the un-slowed budget. This is the intended "statuses take effect when applied" reading;
ruled/flagged in edge-cases so it's explicit and playtest-confirmed rather than surprising.

### 4. [Low — process risk] Three branches edit the same docs
This review branch, the engine branch, and the Designer roster branch have each edited
`docs/design/edge-cases.md` (and BACKLOG). The roster branch's edits aren't merged yet.
**Recommend serializing doc merges** (engine + this review first, then rebase the roster
branch onto the result) so rulings aren't clobbered. Called out in the backlog.

### 5. [Low — guardrail] Roster branch ENGINE ASKs must not be built in v1
`roster-v1.md` §9 proposes new engine mechanics (effect target affinity; energy on
ally-benefit). These are 2v2-era and need explicit rulings; the Builder must not implement
them from the data drafts. Flagged as blocked cross-role items.
