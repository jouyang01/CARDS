## Issues, ranked — the nine Dev Notes, root-caused

### 1. [HIGH — shipped feature unusable] Free actions have no client slot (Dev Notes #6, #7)
*"I cannot use overwatch trap and attack/sprint after"* / *"Veil and Decoy … cannot sprint/attack
after."* **Root cause (client):** there are **zero `freeAbility` references in
`packages/client/src`**. FREE1 was engine-only; the client never built the slot. A `free:true`
ability fills `draft.abilityId` (the *normal* slot); `toUnitOrders` (`targeting.ts:559`) emits it
as `order.ability`; and `app.ts:581` sets `sprintDisabled: draft.abilityId !== undefined`. So the
free ability eats the one ability slot **and** kills Sprint — the exact opposite of "free". The
engine's budget-independence (`resolve.ts:207-209`, `movementBudget(unit, sprint)`) is correct and
unreached. **Fix: backlog FREE-UI** — a `free` ability gets its own draft slot + arm-mode, exactly
as CAT2 did for catalysts; `toUnitOrders` routes it to `order.freeAbility`; Sprint/ability stay
free. Ruled in edge-cases.

### 2. [HIGH — engine correctness] Prep beneficial AoE shields only the caster (Dev Note #3)
*"Aegis Barrier Pulse is only shielding one ally, should shield all allies in the area."* **Root
cause (engine):** `firePrep`'s non-trap branch (`resolve.ts:599-601`) calls
`applySelfEffects(draft, unit, …)` — it applies effects to **the caster alone** and ignores
`a.area`. Barrier Pulse (`circle radius 1` shield, Prep) therefore only ever shields Aegis, not
the aimed ally or the area. The **Blast** beneficial loop (`~:1006`) and the **dash-impact** ally
loop (`~:806`) both iterate allies in `a.area` — **Prep never got that loop.** **Fix: backlog
PREP-AOE** — `firePrep` runs the same beneficial-allies-in-area loop (caster once, no double).
Ships with a two-ally test. Ruled in edge-cases.

### 3. [HIGH — reads as broken] Buffs/debuffs invisible; stealth masked by decoy render (Dev Notes #2, #4)
*"Stealth and Slow are not working, audit … all buffs and debuffs."* **Finding:** the **engine
status math is correct** — Slow shrinks the budget (`movementBudget`, `constants` SLOW_PCT) and
the Move re-clamps down at Move time (`resolve.ts:1099-1102`); Stealth hides via
`isHidden`/`canSee` (`vision.ts:231-232`) so `visibleEnemiesForTeam` excludes it and `fogView`
drops it; durations tick at **end of turn** so a duration-1 status survives its own turn
(`status.ts`). Two real reasons it *reads* as broken: **(a)** no client surfacing — a landed
Slow/Weaken/Root shows no icon or tint, so the player cannot see the debuff took (status icons are
still "observed-not-requested"); **(b)** stealth is delivered by Veil & Decoy, a **free** ability
— unusable-with-the-rest-of-your-turn until FREE-UI — and the **decoy renders wrong** (issue 4),
planting a Wisp-marker on the "hidden" unit's square. **Fix: backlog STATUS-AUDIT** — end-to-end
tests that each of the nine statuses changes a *resolved* outcome, plus client status indicators;
depends on FREE-UI + DECOY-RENDER for stealth to read correctly.

### 4. [MED-HIGH — client] Decoy is not team-aware and not fogged (Dev Note #2)
*"decoy should show as an enemy for the enemy team and a unique purple color for ally team."*
**Root cause (client):** `app.ts:409` draws **all** decoys as bare positions
(`state.decoys.map(d => d.pos)`) — no team styling, no fog gate. **Fix: backlog DECOY-RENDER** —
enemy view = a normal enemy Wisp (indistinguishable); own-team view = a **purple** marker; and
gate it through `visibleSquaresForTeam` like a real enemy. Ruled in edge-cases (R2 rendering).

### 5. [MED — client render] Brush tiles occlude the aim/reach overlays (Dev Note #9)
*"The green stealth squares are STILL hiding aoe effect and movement options."* The green tiles
are **brush** (`BOARD_COLORS.brush = 0x2e4632`); the aim/reach highlight layers render at/under the
brush tile geometry and lose the z-fight, so an AoE or move envelope over brush is hidden. **Fix:
backlog FOG-ZORDER** — lift the highlight layers above the base board tiles (or render brush as a
highlight-compatible layer). Reproduce/verify via RENDER-VERIFY (this is a WebGL layering bug unit
tests cannot see). `renderer3d.ts` + the `app.ts` layer list `['fog','range','reach','aim',
'catalyst','select']`.

### 6. [MED — client] Dash impact area not previewed (Dev Note #8; Builder OQ 2026-08-27 #3)
*"Shadowstep Strike needs to show what boxes are being hit, not just the box of arrival."* DASH-
IMPACT shipped without a preview — `expandShape` returns the landing square only. **Fix: backlog
DASH-PREVIEW** — a client overlay drawing the `impact` disc(s) at the aimed landing (and origin),
reusing `circleSquares`; **not** by overloading `expandShape.a.area` (which is "aimed" at plan
time but the engine detonates at the *actual* rest square). Ruled in edge-cases.

### 7. [MED — new feature] Action preview numbers (Dev Note #1)
*"Preview damage and healing and shielding done above the character model when confirming action
(before locking in) … red (damage), green (healing), blue (shielding)."* **Fix: backlog
PREVIEW-NUMBERS** — while an action is aimed (pre-lock), float the effect amount over each affected
unit, coloured by polarity. Compute from the same `expandShape` area + the ability's effect
amounts the engine uses; read-only, no engine change.

### 8. [DESIGN — route to Designer] Dash catalysts should not be free (Dev Note #5)
*"Dash catalysts should not be free actions."* This **reverses the CAT1 "Shift does not consume
Move" ruling** for the Dash colour — Shift is a free ≤3 teleport that stacks on a full Move.
**Fix: backlog CAT-DASH-COST (blocked on Designer)** — my recommendation: Dash catalysts compete
with dash abilities and spend the Move for their reposition (not additive); Prep/Blast stay free.
The Designer owns the economy call; the Builder holds until ruled. PROPOSED in edge-cases.

### 9. [LOW — hardening] Unknown `AbilityDef` keys still pass silently (Builder OQ 2026-08-27 #5)
`validateAbility` now rejects unknown `impact` members but still accepts unknown top-level keys, so
a typo'd field is dropped without error. **Fix: backlog VALIDATE-KEYS** — a "reject unknown keys"
pass (touches every ability + fixture, hence its own small item).

No correctness defects in the geometry track; the engine bugs are PREP-AOE (Prep AoE) alone.
